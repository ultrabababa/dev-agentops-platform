# DevAgentOps 项目定位

> 本文件是个人学习与面试准备材料，不是实现需求来源。实现范围以 GitHub Issue、V1 PRD、Active ADR 和 `CONTEXT.md` 为准。

## 一句话定位

DevAgentOps 是一个用于秋招展示和系统研究的、可评测的 CI/Test Failure Triage 系统原型：它将研发失败组织为可重放的 Offline Case，通过 Pipeline 或 Single Triage Agent 收集证据、生成 Structured Triage Report，并用 Trace、Evaluation 和 Badcase Carryover 检查系统是否真的改进。

## V1 承诺

V1 只承诺以下闭环：

```text
Offline Case
→ Pipeline Baseline / Single Triage Agent
→ Evidence-backed Structured Triage Report
→ Trace / Manifest
→ Metric Vector / Quality Gate
→ Badcase Review / Carryover
```

V1 结束于结构化诊断报告，不修改代码、不执行测试、不重跑 CI、不创建 PR。真实 CI Provider、OS 级 Sandbox、Multi-Agent、跨运行 Memory 和模型训练均属于未来范围。

## 为什么值得做

### 对求职

它不是用技术名词堆叠的 Agent Demo，而是用一个明确任务证明：

- 我能建设本地可运行的 Agent 系统；
- 我能设计可复现任务、完整 Trajectory 和 Evidence Contract；
- 我能比较 Pipeline 与 Agent，而不是预设 Agent 一定更好；
- 我能用多维指标、Badcase 和 Regression Eval 推进迭代；
- 我能解释权限边界、失败模式和工程取舍。

### 对长期发展

项目可以逐步成为一个小型 Agent Learning Systems 原型。长期关注的问题是：怎样从真实任务执行和环境反馈中，低成本获得高质量、可验证的轨迹、评测数据和候选学习信号。

长期能力路线是：

```text
Agent Engineering
→ Runtime / Trajectory / Reliability
→ Evals & Environments
→ Agent Learning Systems
→ Post-training Data Infrastructure / Research Engineering
```

这个长期目标指导能力积累，但不扩大当前 V1。

## 推进方法

先跑通一个最小端到端闭环，再依据真实瓶颈让 Environment、Runtime、Trajectory、Grader 和 Data 螺旋升级：

- 环境无法复现，就改进 Environment；
- 轨迹缺少关键信息，就改进 Runtime 与 Observability；
- 成功标准模糊或误判，就改进 Verifier / Grader；
- 失败样本重复，就改进 Case 采样和 Hard-case Mining；
- 更新造成退化，就通过新的 Formal Evaluation Run 做 Regression Eval。

书本和实验只在它们能降低下一个项目决策的不确定性时使用，不先把全部内容学完。

## EBDD 内部开发闭环

Evaluation and Badcase Driven Development（EBDD）是内部开发方法，不是对外产品类别，也不替代 TDD。

```text
Formal Evaluation Run
→ Metric Vector / Quality Gate
→ Badcase Review
→ Debug Run / Case Subset Debug
→ 修改 Draft Component
→ Freeze Component
→ Update Evaluation Matrix
→ New Formal Evaluation Run
→ Badcase Carryover
```

- TDD 验证确定性软件行为；
- EBDD 指导 Prompt、Retrieval、Tool Policy、Runtime 和评测组件的行为迭代；
- Debug Run 只能帮助定位，只有新的 Formal Evaluation Run 才能证明修复；
- 使用 Metric Vector 定位问题，不用单一综合分掩盖失败类型。

## 与现有 Coding Agent 的关系

DevAgentOps 不试图替代 Claude Code、Codex、OpenHands 或其他通用 Coding Agent。它聚焦的是 CI/Test Failure Triage 的任务建模、证据契约、可复现评测和治理边界。未来成熟 Coding Agent 可以作为 Runtime Variant 或执行后端接入，但当前 V1 仍使用受控的 Pipeline 和 Single Triage Agent 建立公平基线。

## 表达边界

在没有真实用户和实验数据前，不宣称：

- 已经把排查时间从小时级缩短到分钟级；
- 已经具备企业级真实 CI 接入或自动修复能力；
- 已经形成自动训练、自主学习或成熟商业闭环；
- Agent 一定优于固定 Pipeline。

更准确的表达是：这是一个系统原型与 Research Engineering 作品，价值由可运行性、可复现性、证据质量、实验设计和一次经过正式回归验证的改进来证明。
