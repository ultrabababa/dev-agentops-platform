从终端命令走到 Python main()

这一课把上一课写出的进程契约放回真实世界：理解安装器如何生成 devagentops 命令，并亲手观察一次完整 smoke path。

1. 读懂入口声明

[project.scripts]
devagentops = "devagentops.cli:main"

devagentops：安装后暴露给 shell 的命令名。

devagentops.cli：需要导入的 Python 模块。

:main：在该模块中调用的函数。

安装器大致生成这样的包装器：

from devagentops.cli import main
sys.exit(main())

所以 main() 返回的 0 或 2 最终会成为真实进程退出码。

2. 先预测四步状态

  1. 对不存在的路径运行 status：会不会创建文件？
  2. 运行第一次 db init：数据库会变成什么状态？
  3. 再次运行 status：输出应与 init 有什么关系？
  4. 把目录当数据库文件初始化：stdout、stderr 和退出码各是什么？

3. 亲手运行 smoke path

  1. 进入隔离 worktree，并创建一次性临时目录。
  2. 先 status，确认观察不存在的数据库不会创建它。
  3. init 后再 status，比较两个 JSON。
  4. 故意传入目录作为非法数据库路径，观察错误通道和退出码。
cd /private/tmp/dev-agentops-platform-issue3-20260804
LESSON_DIR="$(mktemp -d)"
LESSON_DB="$LESSON_DIR/devagentops.db"

.venv/bin/devagentops status --database "$LESSON_DB"
echo "exit=$?"

.venv/bin/devagentops db init --database "$LESSON_DB"
echo "exit=$?"

.venv/bin/devagentops status --database "$LESSON_DB"
echo "exit=$?"

.venv/bin/devagentops db init --database "$LESSON_DIR"
echo "exit=$?"

  2. sys.exit(main()) 怎样把 Python 返回值变成进程退出码？
  3. 为什么 smoke test 仍不能替代 pytest 自动化测试？
