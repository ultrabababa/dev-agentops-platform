实现不会创建数据库的 status

这一课只学一个工程不变量：观察状态不应该改变状态。完成后，你会亲手实现一个只读 SQLite 检查器，并用测试证明它不会制造数据库文件。

学习规则：第一次测试通过前，不打开 src/devagentops/storage.py。现成实现是课后的对照答案，不是起点。

1. 先预测，不运行

数据库路径是 /tmp/demo/missing.db，目录和文件都不存在。下面两种实现有何不同？

# A
sqlite3.connect(path)

# B
if not path.exists():
    return {"exists": False}

在纸上写下：哪一个可能改变文件系统？为什么这会让 status 变成不可靠的观察工具？

完成预测后再展开

sqlite3.connect(path) 默认会在父目录存在时创建数据库文件。实现 B 先处理“文件不存在”的状态，可以在连接前返回，因此保持只读。

3. 卡住时只看一级提示

提示 1：安全的控制流
resolve path
→ exists?
→ is file?
→ open read-only
→ query tables
→ close connection
提示 2：只读 URI 形状

先用 Path.as_uri() 得到 file URI，再附加 ?mode=ro，并向 sqlite3.connect(..., uri=True) 明确启用 URI。

提示 3：表名查询
SELECT name
FROM sqlite_master
WHERE type = 'table'
ORDER BY name
