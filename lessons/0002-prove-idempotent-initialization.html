用测试证明重复初始化不丢数据

你已经能解释幂等 Migration。现在把它变成一条回归测试：只要未来有人把初始化改成“删除并重建”，测试必须立刻失败。

学习规则：第一次尝试完成前，不打开 tests/test_issue_3_cli_sqlite.py。你要从安全不变量推导测试，而不是复制现成断言。

1. 先写测试故事

Given  数据库完成第一次初始化，并写入一条用户数据
When   对同一路径再次执行初始化
Then   用户数据仍然存在，迁移版本仍是 0001

这里的 marker row 代替未来真实的 Run 数据。测试关心的不是它有什么业务意义，而是初始化不得删除调用者已经保存的状态。

3. 卡住时逐级展开

提示 1：测试的 Arrange / Act / Assert
Arrange: init → insert marker
Act:     init again
Assert:  select marker → select revision
提示 2：marker 的 SQL
INSERT INTO devagentops_metadata (key, value)
VALUES (?, ?)
提示 3：为什么要 commit

如果写入事务没有提交，连接关闭后可能回滚。那时 marker 消失不能证明第二次初始化清空了数据，只能证明测试自己没有保存数据。

提示 4：读取 Alembic revision
SELECT version_num FROM alembic_version
