两个命令，两种副作用

命令允许禁止
status检查文件、打开已有数据库、查询表创建目录、创建数据库、执行 Migration
db init创建父目录、创建数据库、升级到 Migration Head重复插入元数据、依赖外部服务
核心不变量：观察状态不应改变状态；初始化可以改变状态，但必须幂等。

为什么需要三层

  • CLI：负责解析输入和把错误变成 exit code，不写数据库规则。
  • Storage：负责路径、连接、状态查询和错误语义，不关心终端展示。
  • Migration：负责 Schema 如何从旧版本演进到新版本。

测试的真正问题

  • 缺失数据库执行 status 后，文件是否仍然不存在？
  • db init 执行两次，表和元数据是否保持一致？
  • 数据库路径其实是目录时，错误是否明确且退出码非零？
  • 空 SQLite 文件是否会被误报为“已初始化”？
